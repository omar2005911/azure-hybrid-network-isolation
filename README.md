# Enterprise Hybrid Cloud Architecture & Secure Workload Isolation

## 📌 Architectural Overview
This repository contains the comprehensive design, structural topology, and empirical validation documentation for an enterprise-grade **Hybrid Cloud Network Infrastructure** built within Microsoft Azure. 

The architecture demonstrates a high-security deployment featuring an encrypted **Site-to-Site (S2S) VPN tunnel** that bridges a simulated On-Premises datacenter with an Azure Hub network. Furthermore, it implements a strictly segregated, highly available **Multi-Tier Web Workload** in a Spoke virtual network, utilizing strict perimeter controls and zero-trust routing principles.

---

The core infrastructure is modeled around an optimized **Hub-and-Spoke Topology** designed to isolate distinct business compliance zones:

### 1. Hybrid Connectivity Sub-system (S2S IPsec VPN)
* **Cross-Premises Integration:** Established a secure, encrypted bi-directional connection between the simulated **On-Premises VNet** (`192.168.0.0/16`) and the **Azure Core Hub VNet** (`10.0.0.0/16`).
* **Gateway Orchestration:** Deployed Route-Based Virtual Network Gateways interacting with precisely configured Local Network Gateways to exchange public peering endpoints (`20.232.76.169` <-> `57.152.86.40`) and advertise local address spaces.
* **Traffic Validation:** Successfully validated tunnels with active data plane ingestion (verifying matching symmetric ingress/egress packet counters).

### 2. Isolated Workload Sub-system (High-Availability Web Tier)
* **Micro-Segmentation:** Dedicated a separate **Web Spoke VNet** (`10.1.0.0/16`) specifically isolated from corporate operational networks to minimize exposure surfaces.
* **High-Bandwidth Interconnect:** Provisioned low-latency VNet Peering between the Hub and Spoke networks utilizing Microsoft's global backbone.
* **High Availability Infrastructure:** Fronted a resilient pool of backend Compute resources (`Web-VM01` & `Web-VM02`) via an **Internal Azure Load Balancer (ILB)** acting as a private single-point-of-entry (`10.1.0.6`).
* **Granular Perimeter Security:** Configured strict Network Security Groups (NSGs) bound to backend subnets to guarantee that compute nodes only process sanitized traffic originating from the load balancer frontend.

## 🎯 Strategic Design Decisions & Business Justifications

Unlike generic lab layouts, every configuration parameter in this architecture was selected to map directly onto real-world business compliance and financial constraints:

### A. Zero-Trust Network Segregation via Non-Transitive Routing
* **The Constraint:** On-Premises corporate assets must never have a direct logical path to production web application hosting environments to prevent lateral threat movement.
* **The Solution (By Design):** **Gateway Transit was explicitly disabled** across the Core-to-Web VNet Peering. Because Azure peering is non-transitive by default, the On-Premises environment can reach the Hub but is cryptographically and logically barred from reaching the Spoke network. This achieves total workload isolation without the overhead of complex firewall rulesets.

### B. Internal Load Balancing for Tier-2 Security Architecture
* **The Constraint:** Frontend servers must be shielded from raw internet exposure and only handle orchestrated, audited internal traffic.
* **The Solution:** Deployed an Internal Load Balancer rather than a Public-facing SKU. This preserves an internal-only IP structure, allowing future integration with reverse-proxies, Application Gateways, or Web Application Firewalls (WAF) at a unified corporate edge.

### C. FinOps & Resource Lifecycle Optimization
* **The Constraint:** Avoiding unnecessary operational expenditure (OpEx) generated by unutilized cloud resources.
* **The Solution:** Adopting a strict "Provision-on-Demand" engineering framework. Upon achieving definitive empirical validation, the live cloud infrastructure assets were de-provisioned to prevent idle-state billing (FinOps compliance). The verified architectural state is fully preserved via the empirical evidence below.
